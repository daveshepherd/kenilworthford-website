# kenilworthford-website

The kenilworthford.com website (webpack, plain JS, in `site/`) and the AWS CDK app (TypeScript, in `src/`) that serves it from S3 through CloudFront. Each release is uploaded to its own folder, `/<version>/`, and a CloudFront Function serves the active one.

See [docs/infrastructure.md](docs/infrastructure.md) for the architecture, releases, testing and rollback. Update it in the same change when you change resources, the version router, caching, deploy jobs or tests.

## Projen owns the project config

This is a projen project (`CdkTypeScriptApp` from `projen-modules`). **`.projenrc.ts` is the source of truth.** Don't hand-edit files marked `~~ Generated by projen`: `package.json`, `tsconfig*.json`, `.gitignore`, `.github/workflows/*`, `.projen/*`, `README.md`, `docs/github-configuration.md`. Edit `.projenrc.ts`, then run `npx projen`.

## Commands

| Task | Command |
|------|---------|
| Full build (site build, synth, typecheck, tests, eslint) | `npx projen build` |
| Build the site only | `npx projen site:build` |
| Local dev server | `npx projen site:serve` |
| Unit tests | `npx jest` (site build tests skip unless the site is built) |
| Deploy and smoke test (**deploys to AWS**) | `npx projen deploy` |

Gotchas:
- **The site must be built before synth.** `src/main.ts` fails if `dist/site/<version>/` is missing. The build does this in `pre-compile`.
- **The version is shared by the build and the deploy.** `site/version.js` and `src/version.ts` must agree: `VERSION`, then `dist/releasetag.txt`, then `package.json` (0.0.0 outside a release). Versions must be semver, as the version router matches them.
- **Every URL in the built site must be absolute under `/<version>/`**, except `config.js` and links between pages, which the router resolves. `test/site/build-output.spec.ts` enforces this.
- **Minified pages leave attributes unquoted.** Parse URLs with `referencedUrls()` in `src/smoke-test/checks.ts`.
- **`projen eslint` runs `--fix`** and rewrites files in place.
- **Never run `cdk bootstrap`** against the river-levels accounts: endor-infrastructure manages it.
- Don't run `npx projen deploy` without asking.

## Git and releases

- Conventional commits with only `feat`, `fix` or `chore`. PRs are squash-merged with the title as the commit, and the type sets the release version.
- Each merge to `main` releases and deploys to development, then production. Deploy jobs are generated from `deployments` in `.projenrc.ts`.
